  **I1. A failed or interrupted `--apply` deletes live files** (`scripts/deploy-ftp.sh:200`). Verified.
  - Without `--overwrite`, lftp deletes each file on the server before uploading the new one (DELE, then STOR).

  **I2. Entire finding (a) is real, Important severity: the manifest goes stale after a failed or interrupted deploy** (`deploy-ftp.sh:136`, `:258-261`; `deploy-ftp-state.mjs:35-55`). Verified.

  - On the rollback, `restore` puts back A's old timestamp, the server's copy is newer, and `--only-newer` skips the file.
  - Result: "rc=0 … 0 updated", while B's `index.html` stays live.
  - The same thing happens after Ctrl-C or kill -9, with a second computer that has its own manifest, and with edits made on the server directly.
  - Dropping `--only-newer` alone is not enough. lftp's default upload rule keeps a newer server file unless the size differs, so a same-size change is still skipped (verified).

Simpler: delete the manifest when `APPLY=1`, at the cost of one full upload after any failure. I tested the delete version: the rollback re-uploads A on both server types.
